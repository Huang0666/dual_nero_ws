# P4 文档

## 作用

定义从“已验证执行链”进入“真实物理动作任务”的第一阶段目标。

## 当前阶段定义

P4 不再继续做零散验证，而是开始做一个真正可重复的物理任务闭环。

当前将 P4 正式定义为：

- `无视觉`
- `低风险`
- `固定工位`
- `双臂固定场景任务闭环`

## 为什么先做固定场景双臂任务

当前已经验证通过的是：

- 单臂 MoveIt 规划
- 单臂 `bridge-final-point` 执行
- 只读负例和恢复 SOP

当前还没有进入正式主路径的能力包括：

- `dual_arms` 正式验证
- 双臂协同约束
- 规划级避障
- 视觉输入
- 抓取闭环

所以 P4 不能直接定义成“双臂协调 + 避障 + 视觉抓取”的全量目标。  
更合理的做法是：从 P4 就让双臂进入任务，但先限制在固定场景、固定工位和低风险动作里，把“双臂任务闭环”做稳。

## P4 的正式目标

让系统基于当前 bridge 路线，稳定完成一个真实的双臂物理动作任务，而不是只会发验证命令。

## 推荐任务模型

第一类任务建议采用：

- 左右臂从待机位出发
- 左右臂到达各自固定工作位或操作预备位
- 按预定义顺序完成固定动作序列
- 左右臂回到安全位

说明：

- 如果当前末端执行器或夹爪条件尚不稳定，P4 先不承诺抓取
- 如果现场已经具备低风险夹具环境，也可以把任务定义成“固定工位下的双臂简单拿放前动作”，但仍然属于无视觉任务

## P4 范围

### 包含

- 选择一个真实任务样例
- 固化任务输入、执行步骤、成功标准
- 让双臂都进入该任务，而不是只验证单臂
- 基于当前正式路径完成任务执行
- 沉淀任务启动、执行、恢复、复验文档

### 不包含

- 视觉接入
- 动态障碍物避障
- 正式双臂协同规划
- 复杂抓取

## 推荐验收标准

- 任务可以按固定步骤启动，不依赖临场拼命令
- 双臂实际完成物理动作，不只是日志 `OK`
- 至少连续多次执行结果一致
- 失败后可以按 SOP 恢复
- 可以明确说明任务的边界条件和未覆盖项

## 与后续阶段的关系

- P4 解决“能不能稳定完成一个双臂固定场景任务”
- P5 再解决“双臂协调运动与避障”
- P6 再解决“视觉接入与简单抓取”

## 当前下一步

P4 的下一步不是继续补底层验证，而是把第一个双臂真实任务样例落成正式入口并完成现场验证。  
当前正式任务入口为：

```bash
ros2 run dual_nero_bridge run_dual_arm_task --task dual_prep_sync
```

如果要直接回到固定初始/安全位，可执行：

```bash
ros2 run dual_nero_bridge run_dual_arm_task --task dual_prep_sync --target safe
```

任务配置文件：

- `src/dual_nero_bridge/config/p4_tasks.yaml`
